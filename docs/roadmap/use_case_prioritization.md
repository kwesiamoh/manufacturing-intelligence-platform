# Use-Case Prioritization

## Prioritization criteria

Score candidate use cases against:

1. business impact;
2. data readiness;
3. decision/actionability;
4. implementation effort;
5. governance risk;
6. time to measurable value.

## Recommended order

| Priority | Use case | Why |
|---|---|---|
| 1 | Production/OEE/loss visibility | high business relevance and strong current data model |
| 2 | Data-quality monitoring | protects trust in every downstream use case |
| 3 | Energy intensity & contextual anomalies | clear cost/efficiency link and existing analytics |
| 4 | Reliability failure/downtime Pareto | actionable maintenance prioritization |
| 5 | Short-horizon operational forecasting | useful after baseline planning data is trusted |
| 6 | Condition monitoring | valuable only where suitable labeled sensor data exists |
| 7 | Advanced prescriptive optimization | defer until upstream data and decision processes mature |

## Portfolio evidence

The project already demonstrates all of the first six at portfolio level.

That does not mean all should be deployed simultaneously in a real
organization. A real implementation should start with the smallest set of use
cases capable of producing measurable operational value.
